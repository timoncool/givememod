输入 /givememod。得到适合这项任务的 mod。

一个 Claude Code skill。它看你在做什么，构建合适的小 mod，在终端或桌面版中实时加载，并按你的意见调整。

安装在 GitHub 上加星

为什么

Claude Code mod 是运行在 Claude Code 内部的小插件：输入框上方的信息栏、侧边面板、提示、暂停工具调用、立即响应的命令。几周内出现了 3000 多个公开 mod，几乎都是通用产品。

一项任务需要的更小、更短命：这次迁移的进度条、这次部署的保护、这组测试的监视器。givememod 一分钟写好它，并且知道那 3000 个 mod 积累的经验。

原理

  1. 读懂情境你的请求、工作形态（计划、大量文件、长任务、危险命令、子代理）、会话状态、项目、你的收藏。
  2. 选出一个 mod最小可用的 mod。输入 /givememod 会直接构建并给出备选；没人要求时，遇到长任务会用一行提出：显示什么、在哪里、成本多少。
  3. 用模板构建11 个测试过的模板和 29 个构建块，遵循加载器的规则，写入本会话的 mods 文件夹。
  4. 检查在你看到之前运行 claude plugin validate 和 claude plugin test。
  5. 实时加载第一次 Claude Code 会询问是否为本会话启用热重载；之后每次修改都在回答结束时生效。
  6. 保留喜欢的说"留下它"：mod 进入你的 skills 文件夹，无需安装即在每个会话中加载，下次遇到类似任务时优先推荐。

在哪里可用

终端Claude Code 2.1.287+：信息栏、面板、状态行、提示、暂停的工具调用、命令。
桌面版Claude Desktop 的 Code 标签页，2.1.286+：同样的 mod，绘制为卡片、面板和提示。
其他claude -p、SDK 和 VS Code 面板中钩子也会运行，但不绘制任何内容。

优点和不足

优点

  • 默认零 token：模板不调用模型，也不向上下文添加内容。
  • 每个 mod 在你看到之前都通过 validate 和测试。
  • 临时 mod 随会话结束而消失，保留的会一直跟着你。
  • 安装第三方 mod 前先审查：能访问什么、成本多少、有什么风险。

不足

  • mod 以你的权限运行；Bash 守卫是提醒，不是沙箱。
  • 会话中第一个 mod 会请求启用热重载。
  • mod 只在终端和桌面版 Code 标签页中绘制；在 VS Code 和 claude -p 中钩子照常运行，但不绘制。
  • 在 Claude Code 修复之前，拦截 Bash 的 mod 会让 worktree 子代理中的 Bash 失效。

安装

  1. 添加 marketplace（任意终端）

    claude plugin marketplace add timoncool/givememod

  2. 安装插件

    claude plugin install givememod@givememod

  3. 重启 Claude Code，然后在任意会话中

    /givememod

可以这样说

  • /givememod
  • /givememod 在输入框上方显示计划进度
  • /givememod 任何 rm -rf 都先等我确认

问答

什么是 Claude Code mod？

一个带钩子模块、在 Claude Code 内部运行的插件。它可以在输入框上方绘制信息栏、打开面板、显示提示和状态行、在你回答前暂停工具调用、添加无需模型回合的命令，并为 Claude 提供工具。

会消耗 token 吗？

构建 mod 是一次普通的 Claude 回合。mod 本身不会调用模型（除非你要求），也不向上下文添加内容。

mod 存放在哪里？

临时 mod 位于会话的 mods 文件夹，随旧会话一起清理。保留的 mod 复制到 ~/.claude/skills/<名称>（或项目的 .claude/skills），每个会话都从那里加载。

桌面版能用吗？

能，在 Claude Desktop 的 Code 标签页中。在终端安装一次插件，桌面会话里也能用这个 skill。

mod 安全吗？

mod 以你的权限运行。每个模板都很小且易读，守卫在出错时拒绝执行，第三方 mod 在加载前会被审查。

能分享我做的 mod 吗？

能。在 plugin.json 旁放一个 marketplace 文件，就可以用 /plugin install <mod> --marketplace <owner>/<repo> 安装。
